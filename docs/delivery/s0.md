## S0.3 audit kernel — what was verified

Verified offline on PostgreSQL 16 (pure Java parts compiled with `-Xlint:all -Werror`):

- **24/24 unit tests pass**: `CanonicalJsonTest`, `AuditChainTest`, `FieldDiffAndReasonPolicyTest`, `StrictJsonReaderTest`.
- **Java ↔ database agreement**: the genesis hash computed in Java equals PostgreSQL `digest()` for the same input
  (golden vector in `GoldenVectors.java`), and a tenant provisioned by `platform.provision_tenant()` (real `now()`)
  verifies as intact with the Java verifier.
- **Append as the runtime role**: the exact `AuditService` statement sequence, run as `arrheniq_app` with RLS on,
  sees only its tenant's rows, takes the advisory lock, appends a Java-hashed event, and the DB chain trigger accepts it.
- **Read-back**: the chain re-read from `jsonb` (PostgreSQL reorders keys, adds spaces, keeps unicode such as `—` and `Ü`)
  still verifies — the hash does not depend on how the database renders JSON.
- **Tamper detection**: changing one value in an exported event is detected at that event; a deleted event is detected as a gap;
  an empty chain is reported as broken.
- **Database enforcement**: UPDATE and DELETE on `audit.audit_event` fail with ARQ-AUDIT-002 even for the schema owner;
  the app role has no DELETE privilege at all; a wrong `prev_hash` is rejected (ARQ-AUDIT-004).

Written for CI, not yet run (needs Maven Central + Docker): `AuditServiceIT` (chain from DB genesis, tenant separation,
transaction required, audit context required, reason enforcement with rollback, owner cannot modify, 8 concurrent writers
stay contiguous and time-ordered) and the refactored `ApplicationIT`, both on the shared `PostgresIntegrationTest` base.

### Design decisions taken in S0.3

- `occurred_at` is read with `clock_timestamp()` **after** the per-tenant advisory lock, so event times always follow
  chain order even when transactions overlap. (`now()` is the transaction start time and could go backwards along the chain.)
- `AuditService.record()` requires an existing transaction (`Propagation.MANDATORY`) — an audit event can never be committed
  separately from the change it describes.
- Changes are stored as canonical JSON and read back with a small strict parser (`StrictJsonReader`, exact decimals,
  rejects duplicate keys), so the verifier has no library dependency and behaves the same in the app, a CLI and an
  inspector's offline check.

## S0.4 login, users, roles, site scope — what was built and verified

Design: [ADR 0018](../adr/0018-browser-login-user-matching-and-per-request-authorization.md).

| Area | Implementation |
|---|---|
| Login | OIDC code flow + PKCE via Spring Security (`/auth/login` → IdP → `/login/oauth2/code/arrheniq`); tokens stay server-side; session cookie `ARQSESSION` (HttpOnly, Secure, SameSite=Lax) stored in `platform.spring_session` |
| Tenant | fixed slug (Private/local) or `<slug>.<base-domain>`; session bound to one tenant |
| User matching | `(issuer, subject)` → ACTIVE user; first login links an INVITED user with the same verified e-mail; all denials audited (`LOGIN_FAILURE` + reason) |
| Authorization | permissions + site scope loaded per request (`CurrentUserLoader`); `@RequirePermission("…")` for services, `Access.requireAt(perm, site)` for the record's site; `/api/v1/me` for the SPA |
| Session rules | idle lock (`session.idle_lock_minutes`) → `ARQ-AUTH-LOCKED`; logoff (`session.logoff_minutes`) → store expiry; absolute 12 h → `ARQ-AUTH-EXPIRED`; deactivated user / suspended tenant → `ARQ-AUTH-REVOKED` |
| Re-authentication | `/auth/reauth?purpose=SIGN|UNLOCK` → `prompt=login&max_age=0&login_hint`; callback must be same user with `auth_time` after the request, otherwise the session is ended; single-use evidence (`ReauthGuard`) for signatures |
| Logout | `POST /auth/logout` (CSRF) → OIDC RP-initiated logout; audited |
| Hardening | deny by default (unknown paths 403, `/api/**` 401 problem JSON), CSRF cookie for the SPA, CSP, open-redirect guard |
| Users | `identity.UserInvitationService` (audited invite + role/site assignment); local profile seeds tenants and dev-realm users (`devsupport.LocalDevData`) |

Verified offline: 20 unit tests (`AccessGrantsTest`, `LoginDecisionTest`, `SessionAndReauthPolicyTest`,
`TenantHostsAndRedirectsTest`, `TenantContextTest`) pass; every new SQL statement was run on PostgreSQL 16 as
`arrheniq_app` under RLS (invite, case-insensitive invitation lookup, linking, permission query, session settings;
an invite without audit context is refused). Needs `mvnw verify`: compilation against Spring Boot 4.2,
`SecurityIT` (10 tests), `SessionSettingsTest`, and the updated `ApplicationIT`.

Known follow-ups: JSON serializer for sessions (ADR 0018); Keycloak container IT for the real IdP round trip
(S0.7); architecture rule "every controller method has `@RequirePermission` or `@AuthenticatedOnly`".

### Local walkthrough (after `mvnw verify` is green)

1. `cd infra/compose && docker compose up -d` and wait until Keycloak answers on http://localhost:8180.
2. `cd backend && .\mvnw.cmd -pl app spring-boot:run "-Dspring-boot.run.profiles=local"`. On first start
   the log shows `Local dev tenant provisioned` and `Local dev user invited`.
3. Open http://localhost:8080/auth/login (always start at the app, port 8080; the Keycloak admin console at
   :8180/admin is a different realm and does not know the dev users) and sign in as `smanager` / `dev-password`. You land on
   `/api/v1/me` with your permissions (Stability Manager at site NJ).
4. Re-authentication: open http://localhost:8080/auth/reauth?purpose=SIGN&returnTo=/api/v1/me. Keycloak asks
   for the password again, even though you are signed in.
5. Denial: in a private window sign in as `bmanager` (a Tenant B user). The local app is Tenant A, so you get
   `{"status":"login_failed"}` and a `LOGIN_FAILURE` event with reason `UNKNOWN_USER`.
6. Audit trail: `psql` as `arrheniq_owner`, `SELECT set_config('app.tenant_id','a0000000-0000-4000-8000-00000000000a',false);`
   then `SELECT seq, action, actor_name, changes FROM audit.audit_event ORDER BY seq;`

## S0.5 test library and products — what was built and verified

Design: [ADR 0019](../adr/0019-sql-write-models-for-gxp-records-and-signature-flow.md) (SQL write models,
signature content, approval flow). Null-safety: every package is `@NullMarked` (JSpecify), nullable values are
marked `@Nullable`.

| Endpoint | Permission (at the record's site for products) | Notes |
|---|---|---|
| `GET /api/v1/test-methods?status&q&limit&offset` · `GET …/{id}` | `masterdata.view` | tenant-wide library |
| `POST /api/v1/test-methods` · `PUT …/{id}` · `POST …/{id}/retire` | `test.manage` | retire needs a reason |
| `GET /api/v1/products?status&q&siteId&limit&offset` · `GET …/{id}` | `masterdata.view` | other sites' products are invisible (404) |
| `POST /api/v1/products` · `PUT …/{id}` · `POST …/{id}/submit` · `POST …/{id}/retire` | `product.manage` | editing APPROVED needs a reason, supersedes the signature, returns to DRAFT |
| `POST /api/v1/products/{id}/approve` | `product.approve` + fresh re-authentication | e-signature (meaning APPROVED); approver ≠ last editor/submitter |
| `POST /api/v1/products/{id}/reject` | `product.approve` | reason required |

Every write: `expectedVersion` (409 `ARQ-CONC-001` if someone changed it), validation with all field errors
(400 `ARQ-VAL-001`), field-by-field audit event in the same transaction, reason enforced by the server
(422 `ARQ-AUDIT-010`). `GET /api/v1/products/{id}` shows the signature manifestation (printed name, meaning,
time, VALID/SUPERSEDED).

Verified offline: 53 unit tests pass (9 new: `TestMethodRulesTest`, `ProductRulesAndLifecycleTest`; reason
policy now also requires reasons for RETIRE and REJECT); every new SQL statement ran on PostgreSQL 16 as
`arrheniq_app` under RLS (optimistic-lock update, site-scoped list with `ANY(uuid[])`, escaped search,
e-signature insert and supersede, the DB rejects an ESTABLISHED expiration without a value, other tenants see
nothing). Needs `mvnw verify`: compilation, `MasterDataIT` (8 tests: CRUD + audit diff, validation, permission,
retire reason, full approval with signature and supersede, segregation of duties, reject reason, site scope).

### Try it locally (after `mvnw verify` is green)
Sign in as `smanager` (http://localhost:8080/auth/login), then in the browser dev-tools console:
```js
const xsrf = document.cookie.match(/XSRF-TOKEN=([^;]+)/)[1];
const api = (m, u, b) => fetch(u, {method: m, headers: {'Content-Type': 'application/json', 'X-XSRF-TOKEN': xsrf},
                                   body: b && JSON.stringify(b)}).then(r => r.json());
const me = await api('GET', '/api/v1/me');
const p = await api('POST', '/api/v1/products', {siteId: me.siteIds[0], code: 'MET-500', name: 'Metformin ER 500 mg',
          productType: 'DRUG_PRODUCT', expirationValue: 24, expirationUnit: 'MONTH'});
await api('POST', `/api/v1/products/${p.product.id}/submit`, {expectedVersion: 0});
```
Then sign in as `qapprover` in a private window, open
`/auth/reauth?purpose=SIGN&returnTo=/api/v1/me` (Keycloak asks for the password again), and call
`api('POST', '/api/v1/products/<id>/approve', {expectedVersion: 1, comment: 'Reviewed'})` within 5 minutes.

## How to run it locally

```bash
# 1. local services
cd infra/compose && docker compose up -d        # Postgres :5432, Keycloak :8180, Mailpit :8025

# 2. backend build + all tests (unit + Testcontainers ITs)
cd backend && mvn -N wrapper:wrapper            # once, creates ./mvnw
./mvnw verify

# 3. run the app against the compose database
./mvnw -pl app spring-boot:run -Dspring-boot.run.profiles=local
curl http://localhost:8080/actuator/health      # {"status":"UP"}
```

Keycloak dev realm `arrheniq-dev` (admin console http://localhost:8180, admin/admin): users `tadmin`, `smanager`,
`qapprover`, `bmanager`, password `dev-password`. **Local only — never reuse these values anywhere else.**
