## S1.1 signing groundwork — what was built

| Area | Implementation | Requirement |
|---|---|---|
| Signing intent | `/auth/reauth?purpose=SIGN` must name `recordType`, `recordId`, `recordVersion` (400 otherwise). The `SigningIntent` travels with the pending re-authentication into the evidence; `SignatureService` refuses another record or version with `409 ARQ-ESG-004`. Stored on the signature (`signing_intent_id`) and in the REAUTH_SUCCESS / SIGN audit events. ADR 0019 §4 (amended) | URS-ESG-002, ESG-003 |
| Sessions as JSON | `SessionJson` + `springSessionConversionService`: `<class>\n<JSON>`, allow-listed classes only (Spring Security context, OAuth2 authorization request, saved request, our re-auth records, Instant, Duration, Boolean, String); `ArrheniqUser` Jackson mixin. V13 clears the old Java-serialized sessions. ADR 0018 (follow-up resolved) | URS-SEC-005 (ASVS V5.5) |
| Configurable approval | `kernel.esign.ApprovalLevel/ApprovalPolicy/ApprovalService`: tenant setting `approval.<kind>` (site overrides tenant), NONE / SINGLE / DOUBLE; DOUBLE = REVIEWED then APPROVED by a different person (`403 ARQ-SOD-002`); reject supersedes a partial approval. Products use it; specifications and protocols will. ADR 0019 §6 | URS-MD-004, ESG-001 |
| Frontend | Approve sends the record and version to `/auth/reauth`; product page shows "1 of 2 approvals", the next meaning (Reviewed/Approved) and blocks a second signature by the same person; clear message on `ARQ-ESG-004` | |

Tests: `SessionJsonTest` (round trip incl. a realistic signed-in user; refuses non-allow-listed and tampered types,
ignores old Java-serialized data), `ApprovalLevelTest`, `SessionAndReauthPolicyTest` (intent rules),
`SecurityIT` (SIGN without a record → 400; intent stored), `MasterDataIT` (intent for another record or version →
409, nothing signed; double approval with SoD; reject supersedes the first signature; NONE approves on submit),
`KeycloakLoginIT` (real round trip with an intent and JSON sessions), `navigation.test.ts`.

**Behaviour change for local data:** after V13 runs, everyone signs in once more.

## S1.2 lists and the ICH starter set — what was built

The schema and catalog already existed (V2 `platform.ref_dictionary*`, `platform.ref_protocol_template`; V3
`app.dictionary*`; V10 seed: 24 lists incl. 13 storage conditions, 10 time-point templates; V11 copies the lists to
every new tenant). S1.2 adds the API, the rules and the screen; no migration.

| Area | Implementation | Requirement |
|---|---|---|
| API | `GET /api/v1/dictionaries`, `GET/POST /api/v1/dictionaries/{code}/values`, `PUT …/values/{id}`, `POST …/{id}/retire`, `…/reactivate`, `…/delete`; read `masterdata.view`, write `dictionary.manage` (site values: at that site) | URS-MD-006 |
| Rules | Codes upper-case and fixed after creation (records refer to values by code); site fixed; attributes are a flat object of text/number/boolean (`temp_c`, `rh`, `role` …); changing a value **in use** needs a reason; retire/delete need a reason; **catalog values and values in use are never deleted** (`409 ARQ-MD-010/011`), only retired; site values visible and editable only at their site; lists marked system-managed are read-only (`409 ARQ-MD-012`). Every change is audited (`DICTIONARY_VALUE`) | URS-MD-006, AUD-001 |
| In use | `DictionaryUsage`: the columns that store each list's codes (test methods, spec tests, protocols, studies, components, results). Add a column there when a new table stores list values | URS-MD-006 |
| ICH templates | `GET /api/v1/protocol-templates`: read-only, with the tenant's condition labels; the protocol builder (S1.5) will copy them | URS-MD-007 |
| Screen | **Lists** (side menu): lists grouped by category with counts; values grid with attributes, site, "In use" and "Catalog" badges; add/edit dialog with an attribute editor; retire, reactivate, delete with reason. **ICH templates** tab | |

Tests: `DictionaryIT` (ICH starter set and templates in a new tenant; add/change/retire/reactivate with audit
trail; in-use value: no delete, reason for changes; catalog value: no delete; mistakes deleted with a reason;
site scope; attribute validation; every in-use column exists), `attributes.test.ts`.
